# Study data backup: export/import

Implemented 2026-10-21 for native Android/iOS. Open **Settings > Data Management**. The card uses the existing Button, card border/background, and theme colors. It is available in Mock and Appwrite modes and displays:

> Warning: Importing will overwrite your current local data.

## Export and import behavior

`exportBackup(userId)` reads Subjects, Tasks, StudyBlocks, ReflectionItems, JournalEntries, and Materials belonging to that user as a consistent SQLite snapshot. It writes UTF-8, two-space-indented JSON to `Paths.cache` and opens the native share sheet with `application/json` / `public.json` metadata. Save a copy to your chosen destination. Dismissing the sheet does not establish that a copy was saved. Successful temporary exports remain in cache while other apps read them; the OS can reclaim them later. Write/share errors remove the failed temporary export and preserve study data.

`importBackup(userId)` opens the native JSON document picker and copies the selected document into cache for reading. Cancellation returns `null` and changes nothing. The file is parsed and fully validated before opening a write transaction. Unsupported versions, missing collections/fields, invalid types/dates, duplicate IDs, missing references, nonpositive study intervals, cyclic/duplicate reschedule links, and inconsistent postponement counts are rejected. Files above 20 MB are rejected to limit mobile parsing memory.

Once valid, import replaces only the signed-in user's six collections in one exclusive transaction. SQLite errors roll back all deletions and partial insertions. Old backup IDs are mapped to fresh local IDs; all foreign keys, including `rescheduled_from` and reflection `study_block_id`, are remapped. Source ownership is not trusted, so a backup can be restored to the currently signed-in account without overwriting other accounts.

Imported blocks are inserted without history links, then linked with UPDATE. This preserves `postpone_count` exactly without firing the existing postponement INSERT trigger again. Future reschedules still increment once. Restoring does not pass through scheduling creation rules or re-rate anything: dates, durations, statuses, deadlines and notes are retained. Legacy review schedules are retired when their topics convert into notes. The normal dashboard refresh subsequently flags any expired scheduled blocks as missed.

StudyWorkspace prevents overlapping mutations and sign-out during backup operations, shows a spinner/error, and refreshes all tabs after import. Its existing `demoRevision` reset signal also clears stale Library filters and Reflections subject/note drafts after an import. A canceled import does not reset those drafts.

Backups include study records, notes/URLs, and local material paths. They exclude passwords, authentication sessions, the theme preference, and attachment file bytes. A path exported from another device may not resolve there. This feature is a manual JSON transfer and is separate from the source/history ZIP generated by `scripts/create-handoff.ps1`.

## Version-6 JSON Contract (Version-1/2/3/4/5 Imports Supported)

All six arrays are required, even when empty. A valid empty backup clears the destination user's study records. Export omits `user_id`; import assigns the destination account explicitly. Unknown extra fields are ignored. IDs must be positive safe integers, unique within each collection, and referenced only within this file.

```json
{
  "format": "yotei.study-backup",
  "version": 6,
  "exported_at": "2026-10-21T12:00:00.000Z",
  "data": {
    "subjects": [],
    "tasks": [],
    "studyBlocks": [],
    "reflectionItems": [],
    "journalEntries": [],
    "materials": []
  }
}
```

| Collection | Required record fields |
| --- | --- |
| subjects | id, name, subject_code (1?32 letters/numbers plus spaces, dots, slashes, underscores and hyphens; normalized uppercase), field_of_study (nonempty, max 128 characters), field_colors (one or two distinct comma-separated six-digit hex colors) |
| tasks | id, subject_id, title, description (nullable, max 4,000 characters), deadline (nullable), estimated_minutes, status, postpone_count |
| studyBlocks | id, task_id, start_time, end_time, status (scheduled/active/done/missed), rescheduled_from (nullable), actual_start_time (nullable), break_time_minutes, break_started_at (nullable), break_time_ms, actual_end_time (nullable), actual_study_seconds |
| reflectionItems | id, subject_id, study_block_id (nullable, must reference a completed session), note (nonempty, max 4,000 characters), created_at |
| journalEntries | id, title (1-200 characters), content (1-12,000 characters), created_at |
| materials | id, subject_id, task_id (nullable), title, url_or_note (nullable), local_file_path (nullable) |

`importBackup` returns collection counts after commit. `exportBackup` returns `{uri, counts}` after the share sheet resolves. Neither API backs up SecureStore or changes authentication.

Version 2 replaces each subject's `color` with field metadata. Version-1 files remain importable: the original color is preserved as `field_colors`, and `field_of_study` becomes `General`. Field names/colors are normalized and validated before any replacement transaction. Other collection formats and rollback/account-isolation rules are unchanged. Theme choice is persisted separately on the destination device and is not overwritten by import.

Version 3 adds the six timer fields above. Versions 1/2 receive null timestamps and zero totals, preserving historical untimed done blocks. Version 3 validates nonnegative integer totals, consistency between whole break minutes and precise break milliseconds, active/done timestamp state, completed studied-time arithmetic, and at most one active session. Active/open-break anchors are preserved, so their chosen mode continues across export/import; completed totals stay frozen. Timer metadata never changes scheduled start/end times or rescheduling history. Malformed timer data is rejected before any local records are deleted.

Version 4 adds required subject_code. Exports preserve the code; imports validate it before writing and normalize it on insertion. Versions 1?3 receive GEN-101; version-3 timers are preserved exactly. Only versions 1/2 get empty timer defaults. See the 2026-10-26 bookshelf/duration section of CHANGELOG.md for all files changed in this pass.

Version 5 adds Task.description and replaces reviewItems with reflectionItems. Linked completed-session IDs are remapped on import. Versions 1-4 must contain their legacy reviewItems list; each topic becomes a note, study_block_id is null, and created_at uses last_reviewed_at or exported_at. Their task descriptions default to null. Old next-review dates are validated but not carried into the journal. Version 5 rejects missing/unfinished session references, malformed notes/timestamps and invalid descriptions before deletion. A task may subsequently move subjects without rewriting an existing reflection's original subject.

Settings discards success toasts, including backup notices, per the current UI contract; the native share sheet, button loading states and inline errors remain. Successful imports refresh the chart, notebook materials, task descriptions and reflection journal. Material links remain references; the manual URL/path option stores references, while Browse File Manager copies selected documents locally without uploading. Legacy free-text material metadata is preserved in backups even if it is not an openable link.

Version 6 adds journalEntries. They have no subject dependency: import assigns the destination user_id and fresh IDs. Versions 1-5 default this collection to empty; importing an older snapshot replaces the current account's manual entries with that empty snapshot. Invalid/missing journal arrays in version 6, duplicate IDs, empty/oversized text and invalid dates reject before deletion. Export includes six account-scoped collections consistently; rollback protects existing manual entries as well as study data.

The primary material picker now copies documents to private permanent app storage and persists local_file_path; this keeps them across cache cleanup and restarts. Backups preserve the URI but still exclude file bytes, so a different installation/device may need to pick the original document again. Deleting a material reference does not delete its provider original or an existing saved file. Newly picked unsaved copies are cleaned up when cancelled/replaced.

## Verification and device test

Passed: lint, typecheck, all 79 auth/database/backup tests, Expo dependency compatibility, Android and iOS bundle export. Run the backup regression suite with:

```powershell
npm.cmd run test:backup
```

Native picker/share interaction is not simulated by those checks. On a phone:

1. In Mock mode (USE_REAL_AUTH=false), load demo data and export/save the JSON. Confirm 20 subjects, 40 distinct tasks, 40 materials and six calendar months of blocks/reflections/manual journal entries in the version-6 file. Real-auth Settings hides the demo loader; both adapters can still export/import their local study data.
2. Add a temporary subject or reflection, then import the saved backup. Confirm it is removed and all tabs reflect the restored records. Deadlines and reflection timestamps should retain their original values.
3. Try picker cancellation, malformed JSON, and an unsupported version. Confirm current records remain unchanged and errors are readable. A canceled picker should not show an error.
4. Repeat in both themes. Confirm full-width buttons, 12px spacing, readable warning, spinners, and disabled concurrent actions. Sign Out and Load Demo Data should be disabled while a backup operation is open.
5. Use a second account to verify its records remain unchanged. A restored missed-block history should retain its postponement count; a new reschedule should raise it by exactly one.

Start Metro from the workspace with `npx.cmd expo start --clear` (`npx expo start --clear` in shells without blocked PowerShell shims). Existing custom development builds must include the newly installed native modules; rebuild the development client if the device reports a missing native module.

The implementation follows the SDK 57 [FileSystem API](https://docs.expo.dev/versions/v57.0.0/sdk/filesystem/), [Sharing API](https://docs.expo.dev/versions/v57.0.0/sdk/sharing/), [DocumentPicker cache requirement](https://docs.expo.dev/versions/v57.0.0/sdk/document-picker/), and [SQLite exclusive transactions](https://docs.expo.dev/versions/v57.0.0/sdk/sqlite/).


## Manual Completion and Preferences (2026-10-27)

Version 6 retains the existing columns and now accepts manual Mark as Done records: status=done, actual_start_time=null, actual_end_time set to the action timestamp, actual_study_seconds equal to floored scheduled seconds, and no open/accumulated breaks. This records an explicit manual allocation without pretending the timer ran. Invalid totals/status/breaks reject before replacement. Older untimed done records (null start/end, zero actual seconds) remain valid and use scheduled-duration fallback.

The clock preference, theme, display-name/profile session and auth credentials are excluded from study JSON. Clock/theme preferences stay in device AsyncStorage; names update through the auth adapter/SessionContext. Both auth modes can export/import study records, but demo reset is Mock-only. JSON remains the only supported study-data backup/restore flow; file bytes are not included.
